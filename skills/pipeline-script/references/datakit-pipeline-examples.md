# DataKit Built-In Pipeline Examples

This is the navigation page for examples derived from `/usr/local/datakit/pipeline/*.p`. These files are generated by DataKit, so treat them as production-shaped examples, not files to edit directly.

Commands in the split references use this skill's `./bin/pipeline-check` wrapper. The wrapper uses `bin/pipeline-go` when present, otherwise it falls back to the local `pipeline-go` repository or a `pipeline-go` binary in `PATH`.

## Inventory

Observed built-in scripts:

```text
apache.p consul.p dameng.p elasticsearch.p jenkins.p kafka.p kingbase.p
mongodb.p mysql.p nginx.p postgresql.p rabbitmq.p redis.p solr.p
sqlserver.p tdengine.p tomcat.p
```

## Shared Patterns

- `grok`: primary extraction strategy for text logs; templates often run multiple `grok()` calls as fallbacks.
- `add_pattern`: define local reusable grok fragments for service-specific date formats and multiline blocks.
- `cast`: convert key metrics and IDs after grok; fields not cast may remain strings.
- `group_in` / `group_between`: normalize severity/status only where the script explicitly does so.
- `nullif`: remove placeholder values such as `-`, empty strings, or zero defaults.
- `default_time`: move extracted `time` into point time and remove the `time` field.
- `json` + `drop_key`: used by JSON-native logs such as MongoDB.
- `duration_precision` / `parse_duration`: normalize latency or duration units.
- `drop_origin_data`: used by Consul to remove the original `message` after extraction.

## Validation Caveats

- Do not use `--require-key time` after a script calls `default_time(time)`. Validate extracted time by inspecting `output.time` or `output.time_unix_nano`.
- Do not assume severity is normalized. For example, Tomcat JUL logs keep `ERROR`, while Jenkins maps `SEVERE` to `error`.
- Do not assume captured numbers are numeric. If a script lacks `cast(field, "int")`, values such as Kafka `line`, PostgreSQL `process_id`, Solr `qtime`, and Kingbase `process_id` can remain strings.
- Some successful template runs print debug lines for missing optional fields because fallback grok branches share casts/groups. Use required output keys and final JSON `ok` as the validation signal.
- Use `$'...'` shell quoting or `--message-file` for multiline messages and real tab characters, especially Jenkins and MySQL slow-query samples.
